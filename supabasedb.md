# Supabase Database Migration Guide

This guide covers migrating the database schema from one Supabase project to another (e.g., from Lovable Cloud to a self-hosted or separate Supabase project for production).

---

## Prerequisites

- Access to the **source** Supabase project (Dashboard or CLI)
- A **target** Supabase project created at [supabase.com](https://supabase.com)
- `psql` or Supabase CLI installed locally

---

## Step 1: Export the Schema

### Option A: Using Supabase CLI

```bash
# Link to source project
supabase link --project-ref <SOURCE_PROJECT_REF>

# Pull the current schema (generates migration files)
supabase db pull
```

This creates migration SQL files in `supabase/migrations/`.

### Option B: Using pg_dump

```bash
pg_dump \
  --schema=public \
  --schema-only \
  --no-owner \
  --no-privileges \
  "postgresql://postgres:<PASSWORD>@db.<SOURCE_REF>.supabase.co:5432/postgres" \
  > schema_dump.sql
```

### Tables

#### `profiles`
- `id` (uuid, PK)

- `social_links` (jsonb)
- `created_at`, `updated_at`

#### `apps`
- `id` (uuid, PK)
- `user_id` (uuid, NOT NULL)
- `app_name`, `slug` (unique, auto-generated by trigger)

- `app_icon_url`, `screenshots[]`
- `tags[]`, `tech_stack[]`, `platforms[]`
- `website_url`, `play_store_url`, `app_store_url`, `github_url`, `demo_video_url`

#### `comments`
- `id` (uuid, PK)
- `app_id` (uuid, FK → apps)
- `user_id` (uuid)
- `text` (text)
- `likes_count` (int, default 0)

#### `comment_likes`
- `id` (uuid, PK)
- `comment_id` (uuid, FK → comments ON DELETE CASCADE)
- `user_id` (uuid)
- `created_at`
- UNIQUE(comment_id, user_id)

#### `ratings`
- `id` (uuid, PK)
- `app_id` (uuid, FK → apps)
- `user_id` (uuid)
- `rating` (int)
- `review_text` (text, nullable)
- `created_at`

#### `follows`
- `id` (uuid, PK)
- `follower_id`, `following_id` (uuid)
- `created_at`

#### `saved_apps`
- `id` (uuid, PK)
- `user_id`, `app_id` (uuid)
- `created_at`

#### `app_tries`
- `id` (uuid, PK)
- `app_id` (uuid, FK → apps), `user_id` (uuid)
- `created_at`

#### `app_updates`
- `id` (uuid, PK)
- `app_id` (uuid, FK → apps), `user_id` (uuid)

- `created_at`

## Step 3: Database Functions

```sql
-- Auto-generate slug from app_name
CREATE OR REPLACE FUNCTION public.generate_app_slug()
RETURNS trigger LANGUAGE plpgsql SET search_path TO 'public' AS $$
DECLARE base_slug text; final_slug text; counter int := 0;
BEGIN
  base_slug := lower(regexp_replace(trim(NEW.app_name), '[^a-zA-Z0-9]+', '-', 'g'));
  base_slug := trim(both '-' from base_slug);
  final_slug := base_slug;
  LOOP
    EXIT WHEN NOT EXISTS (SELECT 1 FROM public.apps WHERE slug = final_slug AND id != NEW.id);
    counter := counter + 1;
    final_slug := base_slug || '-' || counter;
  END LOOP;
  NEW.slug := final_slug;
  RETURN NEW;
END; $$;

-- Increment view count (security definer)
CREATE OR REPLACE FUNCTION public.increment_views(app_id uuid)
RETURNS void LANGUAGE sql SECURITY DEFINER SET search_path TO 'public' AS $$
  UPDATE public.apps SET views_count = COALESCE(views_count, 0) + 1 WHERE id = app_id;
$$;

-- Auto-create profile on signup
CREATE OR REPLACE FUNCTION public.handle_new_user()
RETURNS trigger LANGUAGE plpgsql SECURITY DEFINER SET search_path TO 'public' AS $$
BEGIN
  INSERT INTO public.profiles (user_id, display_name)
  VALUES (NEW.id, COALESCE(NEW.raw_user_meta_data->>'display_name', split_part(NEW.email, '@', 1)));
  RETURN NEW;
END; $$;

-- Auto-update updated_at
CREATE OR REPLACE FUNCTION public.update_updated_at_column()
RETURNS trigger LANGUAGE plpgsql SET search_path TO 'public' AS $$
BEGIN
  NEW.updated_at = now();
  RETURN NEW;
END; $$;
```

## Step 4: Triggers

```sql
-- Slug generation on insert/update
CREATE TRIGGER generate_slug_trigger
BEFORE INSERT OR UPDATE OF app_name ON public.apps
FOR EACH ROW EXECUTE FUNCTION public.generate_app_slug();

-- Auto profile creation
CREATE TRIGGER on_auth_user_created
AFTER INSERT ON auth.users
FOR EACH ROW EXECUTE FUNCTION public.handle_new_user();

-- Updated_at triggers
CREATE TRIGGER update_profiles_updated_at
BEFORE UPDATE ON public.profiles
FOR EACH ROW EXECUTE FUNCTION public.update_updated_at_column();

CREATE TRIGGER update_apps_updated_at
BEFORE UPDATE ON public.apps
FOR EACH ROW EXECUTE FUNCTION public.update_updated_at_column();
```

## Step 5: Row-Level Security (RLS) Policies

### profiles
```sql
ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Profiles are viewable by everyone" ON public.profiles FOR SELECT TO public USING (true);
CREATE POLICY "Users can insert their own profile" ON public.profiles FOR INSERT TO public WITH CHECK (auth.uid() = user_id);
CREATE POLICY "Users can update their own profile" ON public.profiles FOR UPDATE TO public USING (auth.uid() = user_id);
```

### apps
```sql
ALTER TABLE public.apps ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Published apps are viewable by everyone" ON public.apps FOR SELECT TO public USING (status = 'published');
CREATE POLICY "Users can view their own apps" ON public.apps FOR SELECT TO authenticated USING (auth.uid() = user_id);
CREATE POLICY "Users can insert their own apps" ON public.apps FOR INSERT TO authenticated WITH CHECK (auth.uid() = user_id);
CREATE POLICY "Users can update their own apps" ON public.apps FOR UPDATE TO authenticated USING (auth.uid() = user_id);
CREATE POLICY "Users can delete their own apps" ON public.apps FOR DELETE TO authenticated USING (auth.uid() = user_id);
```

### comments

## Step 6: Storage Buckets

```sql
-- Create the app-assets bucket (public)
INSERT INTO storage.buckets (id, name, public) VALUES ('app-assets', 'app-assets', true);
```

Add storage policies via Supabase Dashboard → Storage → Policies:
- Allow authenticated users to upload to `app-assets`
- Allow public read access to `app-assets`

## Step 7: Apply to Target Project

### Option A: Supabase CLI

```bash
supabase link --project-ref <TARGET_PROJECT_REF>
supabase db push
```

### Option B: Manual SQL

1. Go to target Supabase Dashboard → SQL Editor
2. Run the table creation SQL
3. Run the functions SQL
4. Run the triggers SQL
5. Run the RLS policies SQL
6. Create storage buckets

## Step 8: Data Migration (Optional)

If you need to copy data:

```bash
# Export data
pg_dump --data-only --schema=public \
  "postgresql://postgres:<PASSWORD>@db.<SOURCE>.supabase.co:5432/postgres" \
  > data_dump.sql

# Import data
psql "postgresql://postgres:<PASSWORD>@db.<TARGET>.supabase.co:5432/postgres" \
  < data_dump.sql
```

## Step 9: Update Environment Variables

In your new deployment, update:

```env
VITE_SUPABASE_URL=https://<TARGET_REF>.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=<TARGET_ANON_KEY>
```

Update `src/integrations/supabase/client.ts` if not using env vars.
